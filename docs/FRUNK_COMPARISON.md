# `typeutils` vs `frunk` 比較レポート

## 1. 概要 (Overview)

`typeutils`（本クレート）と `frunk` は、どちらも Rust の型システムを高度に利用したライブラリですが、その設計思想と目的は大きく異なります。

- **`typeutils`**: **「計算 (Computation)」と「論理 (Logic)」** に焦点を当てています。型レベルでのスタックマシン、評価器（Evaluator）、制御構文（If, While）を提供し、型システム上でアルゴリズムを実行することを目的としています。
- **`frunk`**: **「データ変換 (Data Transformation)」と「構造 (Structure)」** に焦点を当てています。`HList`（異種リスト）、`Coproduct`、`Generic`（構造的部分型付け）を提供し、ボイラープレートの削減やデータの合成・変換を目的としています。

## 2. 機能比較表 (Feature Matrix)

| 特徴               | typeutils                                    | frunk                                      |
| :----------------- | :------------------------------------------- | :----------------------------------------- |
| **主なデータ構造** | `TyArray` (型のみのリスト)                   | `HList` (値を持つリスト)                   |
| **主なパラダイム** | スタックマシン, 命令型/関数型混合            | 関数型データ構造                           |
| **制御フロー**     | `eval::EIf`, `machine::OpWhile` (ループあり) | 再帰的トレイト解決 (基本は分岐のみ)        |
| **構造体変換**     | なし                                         | `Generic` / `LabelledGeneric`              |
| **計算能力**       | 加算、減算、比較、論理演算、ユーザー定義関数 | 型レベル整数 (`typenum`), Semigroup/Monoid |
| **用途**           | 型レベルVM、静的アサーション、DSLの作成      | DTO変換、エラーハンドリング、可変長引数    |
| **依存関係**       | `typenum`                                    | `typenum` (オプション), `paste`            |

## 3. 詳細な違い

### 3.1. リスト構造: `TyArray` vs `HList`

どちらも Cons List（連結リスト）を採用していますが、その役割が異なります。

- **`typeutils::TyArray`**:
  - **純粋な型**: 実行時の値を保持することを主目的としていません（`PhantomData` のみ）。
  - **マシンスタック**: スタックマシンの「メモリ」や「スタック」として機能します。
  - **マクロ**: `tyarray![i32, bool]` のように記述。

- **`frunk`**:
  - **値のコンテナ**: 実行時に値 (`i32`, `String` 等) を保持します。
  - **構造体との相互運用**: 構造体を `HList` に分解し、操作してから構造体に戻すことができます。
  - **マクロ**: `hlist![1, "hello"]` のように記述。

### 3.2. アーキテクチャ: `Evaluator` vs `Recursive Traits`

- **`typeutils` (Centralized Evaluation)**:
  - `Evaluable` トレイトと `Evaluator<T>` エイリアスを中心とした**統一的な評価システム**を持ちます。
  - 式（Expression）を遅延評価的に構築し、最後に `Evaluator` で解決するスタイルです。
  - 例: `type Res = Evaluator<EAdd<U1, U2>>;`

- **`frunk` (Recursive Traits)**:
  - 従来のRustのイディオムである「再帰的トレイト」を多用します。
  - 各操作（例: `Plucker`, `Sculptor`）が個別のトレイトとして定義され、型推論によって解決されます。
  - 統一された「評価器」という概念はなく、各トレイトが独立して動作します。

### 3.3. 実行モデル: VM vs Data Types

最も大きな違いは `typeutils` が **VM (Virtual Machine)** を持っていることです。

- **`typeutils`**:
  - `OpPush`, `OpAdd`, `OpStore`, `OpWhile` などの命令セット（OpCodes）を持っています。
  - プログラム（命令のリスト）を定義し、それを状態遷移させることで計算を行います。
  - **チューリング完全性**を意識したループ構造 (`OpWhile`) を持っています。

- **`frunk`**:
  - データ型としての機能が主です。
  - 「処理」はデータに対する変換（Map, Fold）として記述されますが、命令列を実行する概念はありません。

## 4. 結論と推奨

この2つのライブラリは競合するものではなく、補完的な関係にあります。

### `typeutils` を使うべき場面

- **複雑な型レベル計算**を行いたい場合（条件分岐やループが必要なロジック）。
- コンパイル時に特定の条件を検証する**DSL (ドメイン固有言語)** を作りたい場合。
- 実行時のオーバーヘッドをゼロにしつつ、コンパイル時に計算結果を確定させたい場合。

### `frunk` を使うべき場面

- 異なる構造体間での**データ変換**（フィールドマッピング）を自動化したい場合。
- **ボイラープレート**（`From` 実装など）を削減したい場合。
- 実行時のデータを柔軟に扱いたい場合（例：エラー型の合成 `Coproduct`）。
